# First Level V0.02 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add data-driven wave previews and readable combat feedback while preserving first-level gameplay and mobile layout dimensions.

**Architecture:** `WaveManager` exposes source wave groups, `Economy` returns credited rewards, and `Game` emits small render-effect records plus queued banners. `UIController` and `Renderer` consume those records without owning game rules. A separate same-origin QA page performs browser state injection.

**Tech Stack:** HTML, CSS, JavaScript ES modules, Canvas 2D, Node test runner.

**Spec:** `docs/superpowers/specs/2026-09-06-first-level-v0-02-design.md`

## Global Constraints

- Do not change map proportions, road coordinates, tower-slot coordinates, tower balance, or penetration rules.
- Preserve the fixed battlefield, context panel, and 44px boss HUD slot.
- Do not add a second level, towers, enemies, formal art, audio, persistence, accounts, rankings, or currency.
- Read Wave Preview content from current Wave and Enemy data.
- Use minimal sufficient tests and direct state injection for Wave 8 and Wave 10 browser checks.
